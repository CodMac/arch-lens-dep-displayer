# 交互设计

> 用户功能视角：用户在浏览器中如何逐层理解一个仓库。所有功能均已实现（D0–D7）。

## 1. 核心思路：从宏观到微观

用户从仓库整体开始，逐层下钻到具体代码，每层只呈现一件事：

```
仓库全景（包） → 包（类） → 类（成员 + 类间关系） → 成员（引用方）
```

## 2. 层级模型（由语言维度驱动）

以 Java 为例（`config/dimensions/java.yaml`）：

| 层级 | kind | 内容 |
|---|---|---|
| L1 | PACKAGE | 包（含子包） |
| L2 | CLASS | 类/接口/枚举 |
| L3 | MEMBER | 方法/字段 |

节点 size = 直接子节点数（包=类数、类=成员数），一眼看出模块/类规模。

## 3. 三个关键交互机制

### 3.1 下钻（面包屑）

点击节点进入下一层，顶部面包屑可回退任意层级。URL hash 记忆路径，刷新/分享不丢。

### 3.2 聚焦（扇入/扇出）

右键节点 → 扇入/扇出 → 选深度（1–N 层）。以该节点为根做 BFS，可达子图叠加当前视图，外部锚点灰显。用于「改 A 影响谁」「谁依赖 A」。

### 3.3 过滤（关系类型）

FilterBar 按关系类型（CALL/CREATE/EXTEND/…）过滤图边，只看单一语义。

## 4. 辅助视图

| 视图 | 功能 |
|---|---|
| 仓库全景（Overview） | 顶层包 + 包间依赖边（边宽=依赖条数），首页第一眼 |
| 搜索栏（SearchBar） | 全局搜索 QN/类名/方法名，命中点击直接定位 |
| 信息栏（DataInfoPanel） | 导入时间/元素/类/包/关系统计/关系类型/环数 |
| 指标卡（MetricCard） | 扇出 TOP/扇入 TOP/规模 TOP10（前三高亮） |
| 收藏侧栏（StarPanel） | 收藏节点列表：定位/删除/备注编辑 |
| 源码面板（SourcePanel） | FilePath:Line 展示，复制 + VSCode 跳转 |

## 5. 图内洞察（GraphCanvas）

| 洞察 | 交互 |
|---|---|
| 环（循环依赖） | SCC 成员红框高亮 + tooltip 环号 + 聚焦环按钮 |
| 上帝对象 | 高扇入节点紫描边 + 加粗 |
| tooltip | hover 出 kind/规模/邻居数 |
| 大图控制 | fit/zoom 工具栏 + 环聚焦 + 下钻折叠 |
| 找路径 | 选点模式：起点→终点，最短路径蓝色高亮 |

## 6. 各层视图详述（Java 为例）

### 仓库全景（level=1）

顶层包节点，size=包内类数；包间聚合边 count=依赖条数（仅两端都是真实层级节点的依赖边，剔除 CONTAIN 纯嵌套与 FILE 伪节点）。

### 包（level=2）

包下类/接口/枚举，类间关系边（继承/调用/泛型…）。点击类进入成员层。

### 类（level=3）

类内成员（方法/字段）+ 类间邻接引用方锚点，理解「类为何存在」。
